## 2. 产品目标

### 2.1 要解决的问题

大学生在考试、关系、就业、睡眠和情绪低落等场景中，往往需要一个低门槛、可随时开始的支持入口。现有系统应帮助用户完成以下闭环：

`表达困扰 -> 梳理情绪与事件 -> 获得一个可执行的小行动 -> 留下记录 -> 回顾变化`

### 2.2 MVP 目标

1. 让新用户在 3 分钟内完成首次情绪表达或情绪记录。
2. 让用户在一次对话后获得清晰、温和且不过度承诺的回应及一个自助行动。
3. 让用户能够回顾自己的情绪变化和历史会话。
4. 当出现高风险表达时，让用户快速看到明确的线下求助入口。
5. 让管理员能够管理科普内容并查看脱敏后的运营趋势。

### 2.3 成功指标

| 维度 | MVP 验证指标 |
| --- | --- |
| 激活 | 新注册用户首次完成对话或日记的比例 |
| 核心行为 | 周均完成一次以上对话、日记或练习的用户比例 |
| 留存 | 次日、7 日回访率 |
| 价值感知 | 对话结束后的“这次对我有帮助”正向反馈率 |
| 安全 | 高风险命中后安全求助卡展示成功率、危机回复审核通过率 |
| 内容 | 知识文章阅读完成率、收藏或继续阅读率 |

指标仅用于评估产品体验，不能被包装为心理治疗效果或医疗疗效。

## 3. 用户与角色

| 角色 | 核心诉求 | MVP 权限 |
| --- | --- | --- |
| 学生用户 | 方便表达、获得支持、记录情绪、学习应对方法 | 使用全部前台功能；仅查看和管理自己的数据 |
| 内容管理员 | 发布可信、易懂的心理健康科普内容 | 管理分类、文章、文章状态和封面 |
| 运营管理员 | 了解产品使用情况与安全运行情况 | 查看聚合数据、风险事件处理状态；不默认浏览完整私密对话 |
| 安全管理员 | 维护风险规则、热线和校内资源配置 | 维护危机响应内容、风险事件审计与模型版本 |

MVP 可先由同一管理员账号承载后三类后台权限；正式运营前应拆分角色并记录操作日志。

## 4. 产品范围

### 4.1 本期包含

1. 注册、登录、退出与基础个人资料。
2. 首次使用告知、年龄确认、隐私与敏感信息单独同意。
3. AI 心理支持文字对话、会话管理、流式回复与历史消息查看。
4. 情绪日记：情绪选择、主观评分、触发事件、身体感受与简单生活指标。
5. 情绪趋势回顾。
6. 心理健康知识库：分类、列表、详情、推荐阅读。
7. 管理后台：文章审核与发布、聚合运营数据。
8. 对话风险识别、危机求助卡、求助资源配置和风险审计。

### 4.2 本期不包含

1. 心理疾病诊断、量表诊断结论、用药建议、停药建议或治疗方案。
2. 替代线下心理咨询、医疗急救或 24 小时人工值守。
3. 面向未成年人的开放注册和陪伴式对话。
4. 语音通话、视频咨询、真人咨询师排班与付费结算。
5. 社区、互评、陌生人私信等用户生成内容功能。
6. 将用户私人对话用于公开展示、模型训练或运营营销。

## 6. 核心用户流程

### 6.1 首次进入

1. 用户注册或登录。
2. 展示产品边界：本产品提供心理支持和自助管理，不是医疗诊断或紧急救援服务。
3. 用户确认已满 18 岁，并完成隐私政策、敏感个人信息处理说明和单独同意。
4. 用户选择当前主要困扰，可跳过：
   - 学业与考试
   - 人际关系
   - 恋爱与家庭
   - 睡眠与精力
   - 焦虑与压力
   - 情绪低落
   - 求职与未来
   - 其他
5. 进入首页，提供“开始倾诉”和“记录今天的情绪”两个主入口。

### 6.2 AI 心理支持对话

1. 用户从首页或会话列表发起“新对话”。
2. 页面展示可点击的场景引导，减少空白输入压力，例如“我想把一件事说清楚”“我现在很焦虑”“我睡不着”。
3. 前端调用创建会话接口，获得 `sessionId`。
4. 用户发送文本，前端调用流式对话接口并逐段展示回复。
5. 系统在回复中遵循“理解感受 -> 澄清处境 -> 提供一个小行动 -> 需要时建议线下支持”的结构。
6. 对话结束后，用户可选择记录本次感受、继续对话或查看相关知识文章。
7. 用户可从历史会话中查看、删除自己的会话。

### 6.3 情绪日记

1. 用户选择一个主情绪和强度。
2. 用户可填写事件、想法、身体反应、睡眠/精力等内容；文本均为可选项。
3. 保存后显示当天记录摘要和近 7/30 天趋势。
4. 系统根据用户主动填写的内容，推荐一篇科普文章或一个轻量练习；不输出疾病标签。

评分字段必须明确语义。当前前端样例中的分数颜色逻辑更接近“风险/压力分”，不宜直接展示成“情绪越高越差”。MVP 统一使用以下二选一规则，并在页面上明确标注：

- 方案 A：使用 1-10 分“总体状态”，1 表示很差，10 表示很好。
- 方案 B：使用 0-100 分“压力风险”，0 表示低，100 表示高。

推荐采用方案 A 作为学生端主视图；如保留方案 B，仅在后台或趋势说明中使用“压力风险”名称。

### 6.4 高风险对话

1. 输入前、模型调用前和模型回复后均执行风险识别。
2. 命中“立即危险、自伤自杀、伤害他人、严重失控或急性精神症状”等规则时，暂停普通闲聊式回答。
3. 页面置顶展示安全求助卡，使用明确语言询问用户是否处于立即危险。
4. 卡片提供一键拨号或复制求助信息的资源：
   - 紧急医疗救援：`120`
   - 紧急警情：`110`
   - 全国统一心理援助热线：`12356`
   - 学校心理中心、辅导员或可信任联系人（由学校/运营方配置）
5. AI 只可提供简短、稳定、鼓励立即联系现实支持的文字，不得承诺持续陪伴、替用户保密或暗示可独立处理危机。
6. 系统记录最小必要的脱敏风险事件、命中规则和处理版本，供授权安全管理员审计。

如果运营团队无法提供人工、及时的危机响应，界面不得暗示“已通知老师”“专人将联系你”或“有人正在监控”。

| 编号 | 需求 | 验收标准 |

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |

## 8. 安全、隐私与合规要求

### 8.1 产品安全规则

1. 所有 AI 页面固定展示“AI 心理支持，不替代专业诊疗或紧急救援”的简短入口说明。
2. 对话模型不得声称自己是心理医生、咨询师或已完成诊断。
3. 对医疗、药物、疾病诊断问题，回复应说明能力边界并引导用户联系医生、学校心理中心或当地专业机构。
4. 高风险识别不得只依赖模型提示词，应采用规则、模型分类、输出审核和人工抽检的组合。
5. 危机卡必须是前端强制组件，不能由模型是否提及热线来决定是否展示。
6. 每次发布或修改系统提示词、风险词库、模型供应商或模型版本前，必须通过安全测试集回归。

### 8.2 数据处理原则

情绪、心理困扰和对话内容应按敏感个人信息进行产品设计。MVP 需做到：

1. 明确处理目的、数据范围、保存期限和第三方模型服务商。
2. 在处理前取得单独同意，且用户可在“我的 - 隐私与数据管理”中查看和管理授权。
3. 只收集实现功能所必需的数据；非必要资料不得阻塞核心使用。
4. 会话、日记、风险事件和后台导出遵循最小权限；后台不以“运营便利”为由广泛开放原文。
5. 传输使用 HTTPS；敏感字段和备份加密；密钥与日志不得包含明文密码、令牌或完整私密对话。
6. 提供账号删除、会话删除和数据导出/查询能力，并明确删除生效范围与保留例外。
7. 使用第三方大模型前，完成供应商、数据出境与调用日志的专项评审。

面向中国境内公众提供生成式 AI 服务时，产品负责人应在上线前完成生成式 AI 服务适用性、模型备案/登记信息展示、内容安全和个人信息保护等合规评审；本文件不是法律意见。

## 10. 交互与内容规范

### 10.1 AI 回复规范

正常场景的单轮回复建议结构：

1. 用一到两句复述用户感受或事件，不假设未提供的事实。
2. 提一个可选的澄清问题，避免连续追问。
3. 给出一项低负担、可在当下完成的建议，例如呼吸、记录、联系可信任的人或拆分任务。
4. 困扰持续、加重或影响学习生活时，建议联系校内心理中心、医生或合格的心理服务人员。

禁止使用：

- “你肯定患有……”
- “你只要坚持和我聊就会好起来。”
- “不要告诉任何人。”
- “我已经帮你联系了……”
- 未经专业资质和明确医疗流程支持的用药、诊断、治疗建议。

### 10.2 界面原则

1. 首页先呈现行动入口，不做复杂的心理测评墙。
2. 对话页保持安静、易读；显著但不过度惊吓地提供“需要紧急帮助”入口。
3. 日记表单采用渐进填写，允许跳过非必填项。
4. 图表呈现趋势而非结论，数据不足时显示友好空状态。
5. 管理端适合高频扫描：筛选、时间范围、导出权限、状态和审计信息应清晰可见。

## 11. 上线计划

### 11.1 P0：可试用的安全 MVP

- 账号登录与首次同意
- AI 流式对话、会话历史和删除
- 新建情绪日记与个人趋势
- 知识库浏览
- 高风险危机卡、资源配置和风险审计
- 管理端文章发布与基础数据概览
- 账号注销/删除申请与隐私入口

### 11.2 P1：提高连续使用

- 对话帮助度反馈
- 文章搜索、标签、收藏和个性化推荐
- 日记编辑、删除、导出
- 自助练习库与练习完成记录
- 提示词、模型和风险规则后台版本化

### 11.3 P2：验证后再扩展

- 学校心理中心预约或转介能力
- 匿名聚合校园心理健康报告
- 经专业审核的主题化成长计划
- 语音输入、无障碍体验和多端适配

## 12. 上线验收清单

- [ ] 所有学生端核心路径均通过未登录、普通用户、管理员三种权限测试。
- [ ] 已完成高风险输入、边缘表达、诱导越狱、医疗/药物问答和网络异常测试。
- [ ] 危机卡在规则命中时由前端强制展示，且 `120`、`110`、`12356` 与校内资源可用。
- [ ] 首次同意、隐私政策、敏感个人信息说明、账号删除入口和数据管理入口可访问。
- [ ] 用户仅能访问自己的会话、日记和数据导出。
- [ ] 管理员查看完整敏感内容、导出数据和变更安全配置均有权限控制和审计。
- [ ] 知识库文章经过审核，富文本已进行安全过滤。
- [ ] 模型名称、供应商、提示词版本、风险规则版本和发布时间可追溯。
- [ ] 已完成上线前产品、技术、安全和法务/合规联合评审。

## 13. 外部依据与待确认事项

本产品处理心理健康相关内容，应将其按敏感个人信息采取更严格的最小化、告知和单独同意设计。中国境内面向公众提供生成式 AI 服务还需考虑适用的生成式 AI 管理要求。`12356` 可作为全国统一心理援助热线资源之一，但学校所在地的校内与本地资源应由运营方在上线前核验和配置。

建议在需求评审时确认：

1. 首期服务范围是否只面向已满 18 岁的在校大学生。
2. 是否有具备资质的心理专业人员参与知识内容、风险规则和测试集审核。
3. 是否有真实的人工风险处置能力；若无，产品只提供明确转介，不承诺人工联系。
4. 第三方模型服务商、模型备案/登记信息、数据存储地域和数据保留策略。
5. 学校心理中心、辅导员、医院等本地求助资源的责任主体与更新机制。
